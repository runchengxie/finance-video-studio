# 本地数据目录

在已配置的数据根目录下，用 `finance-video-studio/` 保存本项目的资料。当前程序仍要求显式提供绝对外部输出路径，不会自动发现或创建这套目录。

```text
finance-video-studio/
  README.md
  catalog.json
  experiments/<project-id>/
  runs/<topic>-<YYYYMMDD>/
  maintenance/<task-id>/
```

本地 README 提供导航，`catalog.json` 可列出相对路径与已存在的材料。这份清单只记录材料位置，不能用于批准稿件，也不能直接作为渲染输入。具体机器路径、私人研究题目和文稿不能进入公开代码仓库。

`experiments/` 保存历史独立工程，`runs/` 保存任务稿件、审阅、素材及输出，`maintenance/` 保存迁移证据。历史工程沿用原标识与内部目录，不能假定每个任务采用相同渲染器。

同一工程的脚本、依赖锁和相对引用的 `src/`、`public/`、`output/` 应一起保留。README 应写清需要保留哪些原始输入，以及哪些文件可以重新生成。输出目录可能还含有独有稿件、封面和交付记录，不应整体当作缓存删除。

迁移前检查目录联接、路径清单、运行任务和下游引用，记录原文件哈希。迁移时拒绝覆盖目标，修复依赖联接与媒体拼接清单，再核对新位置的哈希及引用。迁移记录放入 `maintenance/<task-id>/`。兼容联接可以保留旧入口，新命令仍使用规范路径。

复用 `node_modules` 时要在各工程说明中明确记录。需要独立安装时，仅解除该工程的联接，再按本工程锁文件安装；不要递归删除共享目标。

正式渲染输出和审阅记录支持与源码分处不同 Windows 盘符；仓库内部路径仍会拒绝，包括名称以两个点开头的子目录。

目录整合不会自动移植历史实验的配音、混音、缓存和章节能力，也不构成事实核验或新的文稿批准。可复用能力需要用原创代码和合成材料适配，继续保留当前哈希绑定的人类批准要求。

## 只读保留资料盘点

清理前运行 `npm run studio -- storage-audit /absolute/project-data /absolute/new-report.json`。报告对同尺寸候选文件计算内容哈希，按不同设备与 inode 区分真实副本，将已经共享的字节与同一文件系统内潜在节省分开列示；列出符号链接但不跟随，跳过 `.git`、`node_modules`、`.venv` 和 `venv` 目录树。统计使用文件大小，不代表实际分配的磁盘块；扫描树之外的硬链接和活跃消费者还需单独检查。命令不删除、不移动、不改权限，也不创建硬链接。输出报告必须使用新路径。

哈希相同不等于可以清理。独有稿件、审核记录、证据、原音和交付记录必须保留。另行获得授权后，若对不可变文件以硬链接保留全部路径，应记录原始元数据、哈希与替换路径，逐项验证结果；后续修改创建新文件，不覆盖共享 inode，也不把重复报告当作自动清缓存指令。预览优先采用原生按时间绘制方式，减少重复导出 HTML/PNG 帧；每期保留稳定场景缓存，正式 MP4 留到具体版本获批后生成。
