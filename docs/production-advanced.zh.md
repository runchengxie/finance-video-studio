# 竖版制作、数字证据与定位审阅

原生 v2 现在支持两种明确规格：**1920×1080、30 fps** 和 **1080×1440、60 fps**。一起设置 `width`、`height`、`fps`，镜头、字幕和事件均按该规格的整数帧计时。旧项目保留原先声明的规格。[原创竖版示例](https://github.com/runchengxie/finance-video-studio/blob/main/examples/portrait.json) 只含虚构数据，没有配音；使用项目命令前先复制到外部目录，并走正常的精确快照批准流程。

竖版使用独立排版，不裁切横版画面。支持数字卡、对比图、含负值对比、趋势图、瀑布图、流程与证据文本，并保留来源。章节、标题补充、数字列表、重要说明及强调动作也会呈现。信息过密时检查报错，不静默丢字。外部背景视频和原文图片面板目前使用横版，竖版请求这些功能会明确拒绝。历史 HTML 工程保持原样，需要明确映射到原生镜头；新增规格不会自动转换旧代码和稿件。

## 共用视觉配置

批准前设置 `render.visual`。

```json
{"preset":"warm-paper","motion":"subtle"}
```

`preset` 可选 `warm-paper` 或 `navy`，用于视频和生成的封面。`motion` 可选 `static` 或 `subtle`。轻微纹理移动按全局帧时间计算，跳转和分段边界的相位一致；持续移动需要逐帧生成，比静态模式更耗时。竖版默认米白风格；不填这项时，既有横版保持兼容。视觉配置和渲染器版本均纳入批准快照。

## 复用未改镜头，继续失败任务

同一期沿用稳定的外部缓存目录，每次构建用新输出目录。整片仍由完整快照授权；缓存另按镜头、相关字幕、全部事件引用字幕（包括通过偏移触发动画的场景外字幕）、来源、图片和背景哈希、规格、视觉配置、工具及渲染器版本计算。修改局部字幕会重做受影响镜头，其他镜头可复用。全局标题、时间、风格或渲染代码变化可能影响更多片段。换音频后仍会重新合并和校验，无需因此丢弃未变的画面。

复用的片段必须有匹配的凭证、文件哈希与解码结果。正常失败后，已完成片段仍可在新构建中使用。渲染锁只自动恢复同一主机上已确认退出的进程，通过独占保护锁串行处理；活跃、异地主机、旧版或格式未知的锁不会被删除。保护锁若异常遗留，需要人工核对，不能冒险自动删除。不要删除运行中任务的锁。

## 关联数字、画面与资料

在清单里配置可选的 `numericClaims`。

```json
{
  "id":"revenue-q3", "cueId":"cue-revenue", "sceneId":"comparison",
  "targetId":"revenue", "value":40, "unit":"亿元", "period":"Q3",
  "scope":"虚构公司合并口径", "sourceIds":["source-q3"],
  "status":"actual"
}
```

`status` 可选 `actual`、`guidance`、`estimate`，分别记录实际、指引和估算；可用 `calculation` 留存公式。记录须引用与镜头重叠的字幕、真实画面目标和该镜头关联的资料。`studio audit` 会报告缺少记录、图中数值或单位不一致，以及趋势图期间不匹配或无法定位的问题。数值、单位应使用图中同一量纲，换算过程写入 `calculation`。这些是口径一致性检查，不能证明资料真实、因果成立或每个口播数字都已覆盖。只表示日期的字幕可人工确认后保留不配图的原因；流程和证据文本中的数值仍需编辑判断。

## 按时间定位审阅

```sh
npm run studio -- review-page /absolute/project.json /absolute/completed-build /absolute/new-review
```

命令生成**内部**本地审阅页，包含匹配的视频、配置的原始音轨、字幕、数字问题、声明详情、资料链接与内部备注。点击字幕跳转，也可使用 `index.html#cue=CUE_ID`。页面可切换中英文。本地播放不需要网络，打开外部原始资料链接是单独操作。导出前检查当前快照、原生构建和媒体哈希，复制的本地资料也会重新计算哈希。本页不渲染稿件、不授予批准、不修改正式 MP4；审阅目录应留在内部。

## 比较语音版本

```sh
npm run studio -- compare /absolute/before.json /absolute/after.json /absolute/new-comparison
```

详见[旁白版本比较](narration-comparison.md)。它对齐已有转写，列出数字、日期和单位变化以及受影响镜头，保留两版清单快照。它不识别或听取 WAV；音频身份按清单声明的哈希比较，并明确标记未经验证。新语音需要先转写与听校，再将报告作为修订依据。
